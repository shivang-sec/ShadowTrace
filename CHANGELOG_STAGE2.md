# ShadowTrace — Stage 2 Changelog: FastAPI Backend Adapter

## Overview
Stage 2 adds an asynchronous REST API layer around the existing ShadowTrace assessment engine without modifying any code inside `shadowtrace/`. The original Python engine remains the sole source of truth for host discovery, risk scoring, baseline checks, vulnerability intelligence, and NVD CVE correlation.

---

## What Was Added

### 1. FastAPI Application & Architecture (`api/`)
- **`api/main.py`**: FastAPI application entry point with CORS middleware configured for cross-origin development and health checks.
- **`api/models.py`**: Pydantic models for input validation (`ScanRequest`), profile selection (`ScanProfile`), status monitoring (`ScanStatus`, `ScanJob`), and report summaries (`ReportSummary`).
- **`api/routes/scans.py`**: Endpoints to start scans (`POST /api/scans`) and poll scan status (`GET /api/scans/{scan_id}`).
- **`api/routes/reports.py`**: Endpoints to list reports (`GET /api/reports`), retrieve a full assessment (`GET /api/reports/{report_id}`), download report JSON (`GET /api/reports/{report_id}/export`), and delete reports (`DELETE /api/reports/{report_id}`).
- **`api/services/scan_service.py`**: Service layer executing the blocking ShadowTrace engine within a `ThreadPoolExecutor`, updating job state, and managing persistent report storage.

### 2. API Endpoints
| Method | Endpoint | Status Codes | Description |
|---|---|---|---|
| `GET` | `/api/health` | 200 | Liveness check returning service status, version, and server timestamp |
| `POST` | `/api/scans` | 202, 422 | Submits scan target and profile (`quick`, `standard`, `deep`); returns `job_id` |
| `GET` | `/api/scans/{scan_id}` | 200, 404 | Polls scan progress: `queued` → `running` (with stage) → `completed` or `failed` |
| `GET` | `/api/reports` | 200 | Lists compact summaries of all completed assessments, newest first |
| `GET` | `/api/reports/{report_id}` | 200, 404 | Retrieves full assessment JSON matching CLI output format |
| `GET` | `/api/reports/{report_id}/export` | 200, 404 | Downloads full assessment as an attached `.json` file |
| `DELETE` | `/api/reports/{report_id}` | 204, 404 | Deletes a stored assessment JSON file and removes it from the index |

### 3. Background Scan Execution
- Nmap discovery and NVD lookups are synchronous and blocking. The API uses Python's `ThreadPoolExecutor` and `asyncio.get_running_loop().run_in_executor` to offload execution from FastAPI's event loop.
- Client requests return immediately (`202 Accepted`) with a tracking `job_id`.
- Scan status transitions are maintained in an in-memory job registry (`queued` → `running` [discovery/analysis] → `completed` / `failed`).

### 4. Local JSON Report Persistence
- Reports are stored locally in the `reports/` directory:
  - `reports/index.json`: Chronological metadata index of completed scans (`report_id`, `target`, `profile`, `timestamp`, `host_count`, `overall_risk`, `exposure_score`).
  - `reports/<report_id>.json`: Complete assessment output generated by the existing ShadowTrace engine.
- Persistent files are ignored in `.gitignore` via `reports/*.json`.

### 5. Input Validation & Error Handling
- Targets are validated against empty inputs, length restrictions (max 256 characters), and shell injection characters (`;`, `&`, `|`, `` ` ``, `$`, `>`, `<`, `!`).
- Profiles are strictly validated against allowed enums (`quick`, `standard`, `deep`).
- Invalid requests return structured HTTP 422 responses.
- Engine failures (e.g., unreachable hosts, missing nmap binary) transition job status cleanly to `failed` and record the error without crashing the server.

### 6. Dependency & Project Metadata Updates
- Updated [`pyproject.toml`](./pyproject.toml) and [`requirements.txt`](./requirements.txt) to include:
  - `fastapi>=0.115.0`
  - `uvicorn[standard]>=0.30.0`
- Extended `pyproject.toml` package discovery to include `api*`.

## Important Environment Limitation
- **Nmap Host Execution**: The ShadowTrace discovery module depends on the system `nmap` binary and raw-socket access (for SYN scans). In the target deployment architecture, the FastAPI backend and ShadowTrace engine run on **Kali Linux** (where Nmap is installed and runs with appropriate permissions), while the frontend is developed on Windows. Running scans on Windows without Nmap installed on `PATH` will result in a caught `PortScannerError` and a `failed` job status.
